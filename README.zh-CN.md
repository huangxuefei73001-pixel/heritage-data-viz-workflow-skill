# Heritage Data Viz Workflow

**一个将大量遗产资料转化为结构化数据、证据型可视化与 Poster 的 Skill。**

这个 Skill 的重点不是“帮你画一张图”，而是解决一个更前置的问题：面对多年报告、文章、案例、届次、国家、主题和关键词，应该如何先整理信息，再找到真正值得被看见的关系，最后把它压缩成一张可阅读、可追溯、可出版的 Poster。

## 核心工作链

**资料库 → 分类体系 → 视觉问题 → 证据图形 → Poster**

Poster 是最后一步，不是第一步。

## 最适合的任务

- 多年观察报告与大会观察资料
- 遗产文章库、案例库、研究资料库
- 世界遗产大会届次与议题分析
- HIA、SOC、申遗、政策与定期报告研究
- 需要对外传播的数据密集型研究
- Poster、明信片、展览、出版与作品集视觉

## 核心视觉机制

### 径向时间图

表现“时间 + 重复出现 + 主题密度”。适合多年序列与届次数据。

[打开径向时间图样例 →](examples/01-radial-wheel.svg)

### 关键数字总览

只选 3–5 个最重要的数字，让读者先理解规模，再进入细节。

[打开关键数字样例 →](examples/02-metric-summary.svg)

### 关系流向图 / Sankey / Alluvial

表现分类之间的连接关系，例如主题 → 年份/届次、主题 → 主办国、来源 → 议题 → 输出。

[打开关系流向样例 →](examples/03-relationship-flow.svg)

### 局部径向 / 分栏构图

将标题、项目入口或来源信息，与复杂的圆形数据可视化放在同一张 Poster 上。

[打开分栏构图样例 →](examples/04-split-field.svg)

## 正反面逻辑

如果是明信片或双面 Poster，正面负责“看见关系”，背面负责“理解项目”：项目简介、线性时间轴、来源、设计署名与访问入口。

[打开背面信息样例 →](examples/05-context-back.svg)

## 最重要的设计原则

> **不是把所有数据放上 Poster，而是把数据能够证明的那条关系放上 Poster。**

因此，这个 Skill 会先：

1. 检查原始资料；
2. 确定分类维度；
3. 核对总量、缺失与歧义；
4. 生成时间、矩阵、流向或网络关系；
5. 只选择一条最值得传播的关系；
6. 再决定是径向图、Sankey、关键数字、地图还是时间线；
7. 最后完成 Poster 构图与导出。

## 视觉语言

### 深色分析模式

适合复杂径向图和高密度定量信息：

- 深灰/墨色背景；
- 米白主文字；
- 稳定的主题色；
- 细线结构；
- 大数字与紧凑图例；
- 颜色只承担分类或重点信息。

### 暖纸编辑模式

适合 Sankey、解释型图形与印刷输出：

- 暖白纸张底色；
- 墨黑文字；
- 克制的分类色；
- 出版式留白与分栏；
- 细线、图例、图注和来源结构清楚。

两种模式都避免：仪表盘式卡片、渐变、重阴影、通用 AI 图像以及没有数据意义的装饰。

## 人工审核边界

AI 可以协助：提取、清洗、初步分类、统计、图形原型和布局方案。

但以下环节必须由人审核：

- 分类体系是否成立；
- 歧义记录如何归类；
- 趋势和解释是否过度；
- 图中的数字是否能追溯到原始资料；
- 最终文字、署名、隐私与版权。

## 样例说明

`examples/` 中的 SVG 是用于说明 Skill 工作方式的确定性视觉语法样例，不替代原项目证据，也不虚构具体项目的数据关系。

## 完成标准

一张 Poster 完成的标准不是“信息很多”或“图很复杂”，而是读者能够快速回答：

**我在看什么？它说明了什么关系？这个判断基于什么证据？**
